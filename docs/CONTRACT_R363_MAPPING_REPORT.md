# R3.6.3 — отчёт по структурной разметке

## Итог

Этап не объявлен завершённым. Source-of-truth проверен: 40 фактов, 19 правил, 25 RF, 74 логических вхождения, 140 физических вхождений после раскрытия `BOTH`, 120 prompt fixtures. Оригинальные DOCX не изменялись и не добавлялись в Git.

## Реализованный discovery

`training_mapping.py` переводит координаты матрицы в version-pinned locator `part#/p[...]` либо `part#/tbl[]/tr[]/tc[]/p[]`. Поиск не выбирает первое совпадение текста. Каждый кандидат содержит вариант, RF, matrix location, locator, fingerprint структуры, диапазон, операцию и статус.

Получено 42 `CANDIDATE_FOUND`, 78 `REVIEW_REQUIRED`, 20 `NOT_FOUND`. Статус кандидата не равен готовой привязке и не повышается автоматически до `CONFIGURED`.

## Review в конструкторе

Для специалиста ДПО добавлены защищённые endpoints списка и решения по кандидату. В `/templates` видны RF, координата, операция, контекст и переход к структурному узлу. Доступны «Подтвердить» и «Отклонить». Изменение разрешено только для DRAFT; решение записывается в audit trail. Подтверждение специально не создаёт binding без проверки семантики операции.

## Идемпотентность

Импорт объединяет кандидаты по `candidate_id` в `TemplateVersion.preview_metadata`, сохраняет ранее принятое решение, не дублирует продукт и поля и не меняет опубликованные версии. Публикация и добавление в пользовательский каталог не выполняются.

## Что не доказано

Bindings, conditional regions, repeating groups и text expressions для 25 RF не созданы автоматически. Контрольные DOCX не сформированы; поэтому нет статусов `GENERATED_AND_VERIFIED`. Матрица содержит 20 координат, для которых соответствующий узел отсутствует в read-only adapter, и 78 мест, где содержимое узла не совпадает с ожидаемым красным текстом. Эти случаи требуют структурной проверки, а не небезопасного глобального поиска.
