# Диалоговый workflow

Контекст строится только из текущего пользователя и обращения: ограниченная история, актуальный черновик ТЗ и workflow state. Модель возвращает `RequirementsExtractionResult`; неизвестные или невалидные поля не записываются. Из одного сообщения извлекаются несколько требований. Обновления применяются только к затронутым полям, удаления — к указанным фрагментам. Недостающие сведения превращаются в один краткий вопрос.

Mock детерминированно поддерживает ноутбуки, велосипеды, сайт/лендинг, уточнения, сроки, добавление и удаление требований. Подтверждение и рекомендация договора остаются под контролем существующего backend workflow и Rules Engine.
