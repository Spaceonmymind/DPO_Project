# Диалоговый workflow

Контекст строится только из текущего пользователя и обращения: ограниченная история, независимый ProcurementContext, актуальный черновик ТЗ (если есть) и workflow state. Модель возвращает `RequirementsExtractionResult`; неизвестные или невалидные поля не записываются. Из одного сообщения извлекаются несколько требований. Обновления применяются только к затронутым полям и позициям, удаления — к указанным фрагментам. Недостающие сведения превращаются в один краткий вопрос.

Три входных сценария используют один case/chat:

1. `GET_CONTRACT`: собираются только договорно значимые признаки; ТЗ не создаётся.
2. `CREATE_SPECIFICATION` / `CREATE_SPEC_AND_GET_CONTRACT`: формируется и подтверждается ТЗ, затем при необходимости запускается Rules Engine.
3. `ANALYZE_SPECIFICATION`: один загруженный документ разбирается, показывается как структурированное ТЗ и после подтверждения используется вместе с ProcurementContext.

Mock детерминированно поддерживает contract-only, ноутбуки, велосипеды, сайт/лендинг, уточнения, сроки, изменения позиций, добавление и удаление требований и fallback в ДПО. Подтверждение и рекомендация договора остаются под контролем backend workflow и Rules Engine.
