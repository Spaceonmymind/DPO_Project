# Ручной test-drive для специалиста ДПО

1. Войти под специалистом ДПО и открыть `/templates` → «Шаблоны DOCX».
2. Открыть договор тренировок нужного варианта и его draft-версию.
3. В блоке готовности использовать фильтры RF, статус и операция. Нажатие RF прокручивает preview к структурному узлу; raw XML не показывается.
4. Для неоднозначного места проверить контекст, нажать «Подтвердить», затем «Создать привязку» только для поддерживаемого `REPLACE`. Ошибочное решение можно отменить в DRAFT.
5. Пакетная материализация работает только для отдельно выбранных и ранее подтверждённых кандидатов; кнопки «подтвердить всё» нет.
6. Операции `DERIVED`, условные блоки, колонки и графики настраиваются соответствующими визуальными инструментами конструктора, а не обычной заменой.
7. На этапе «Проверка и публикация» заполнить test-drive анкету. Кнопка генерации активируется только при отсутствии незавершённых кандидатов.
8. Сформированный файл скачивается как тестовый. В header и свойства DOCX встроена отметка `ТЕСТОВЫЙ ДОКУМЕНТ · НЕ ДЛЯ ПОДПИСАНИЯ`.

Сейчас шаг 7 намеренно заблокирован: остаются 132 места настройки и 4 структурных блокера. Публикация для test-drive не требуется и автоматически не выполняется.
