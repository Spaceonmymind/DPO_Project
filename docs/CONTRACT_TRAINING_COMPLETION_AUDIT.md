# Проверка настройки двух договоров тренировок

## Текущее состояние

Проверены DRAFT-версии ИП `4eff6663-f03e-4858-bb2a-6dc39b4b1b95` и ФЛ `3dbdc61e-953b-49ce-a5c7-57df2613e454` на исходных DOCX и матрице `Матрица_применимости_LLM_v2.xlsx`. Перед изменением PostgreSQL создана резервная копия `/tmp/dpo-rf-config-XXXXXX.dump` в custom format PostgreSQL; её каталог прочитан `pg_restore` из контейнера PostgreSQL 16. Оригиналы и матрица имеют утверждённые SHA-256. Версии и продукт не опубликованы.

Покрытие 140 физических кандидатов: `CONFIGURED` 105, `STRUCTURAL_ALIAS` 16, `REVIEW_REQUIRED` 17, `BLOCKED` 2. Итого 121 технически разрешён, 19 требуют решения. Защищённый `draft_test_drive` вернул `409` для ИП (9 кандидатов) и ФЛ (10 кандидатов). Официальные контрольные DOCX не сформированы.

## Диагностические DOCX

Без регистрации в `GeneratedDocument` создано шесть файлов:

- `storage/rf010-diagnostics/rf010-vat_payer.docx`
- `storage/rf010-diagnostics/rf010-no_vat.docx`
- `storage/training-combined-diagnostics/ip-guarantee-0.docx`
- `storage/training-combined-diagnostics/ip-guarantee-1.docx`
- `storage/training-combined-diagnostics/physical-guarantee-0.docx`
- `storage/training-combined-diagnostics/physical-guarantee-1.docx`

Четыре совместных сценария прошли ZIP integrity, открытие `python-docx`, проверку условных абзацев, двух графиков по две тренировки, вычисленных сумм строк, условных строк RF022, RF008 и RF014. Рендер страниц в PNG не состоялся: доступный пакетный `render_docx.py` завершается на отсутствующей зависимости `pdf2image`. Следовательно, визуальная Word/LibreOffice-приёмка ещё не выполнена. Эти файлы служат технической диагностикой, а не готовыми договорами.
