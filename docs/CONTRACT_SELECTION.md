# Выбор утверждённого шаблона договора

Система не генерирует и не редактирует договоры. LLM извлекает факты в `ProcurementContext`, детерминированный Rules Engine выбирает код, registry разрешает код в оригинальный файл.

## Реестр

| Код | Название | Исходный файл |
|---|---|---|
| `SUPPLY` | Договор поставки | `договор поставки.rtf` |
| `SERVICES` | Договор возмездного оказания услуг | `договор возмездного оказания услуг (образец).docx` |
| `WORKS` | Договор подряда | `Договор_подряда.docx` |
| `AGENCY` | Агентский договор | `Shablon-agentskogo-dogovora.docx` |

Registry хранит имя, формат, версию, путь, активность и SHA-256. Исходники лежат в ignored-каталоге `contract_templates/`, отдельно от uploads и generated files. В контейнер он монтируется read-only: `./contract_templates:/app/contract_templates:ro`.

## Правила

- `SUPPLY`: передача товара без самостоятельного комплекса работ, услуг или агентских действий.
- `SERVICES`: деятельность без передаваемого материального результата работ.
- `WORKS`: конкретный результат работ и его приёмка.
- `AGENCY`: действия по поручению и в интересах принципала; характерны третьи лица, отчёт и отдельное вознаграждение.

При одновременных признаках товара и работ/услуг статус — `AMBIGUOUS`; система спрашивает, какой элемент является основным. Неполные агентские признаки также требуют уточнения. Непокрытый сценарий возвращает `NO_MATCH`, исключения — `LEGAL_REVIEW_REQUIRED`; оба направляют пользователя в ДПО. `rules_triggered` содержит только идентификаторы правил, не внутренние рассуждения модели.

Статусы: `MATCHED`, `AMBIGUOUS`, `NO_MATCH`, `LEGAL_REVIEW_REQUIRED`.

## Безопасная выдача

`GET /api/v1/cases/{case_id}/contract-template` требует авторизацию и владение обращением, проверяет привязанную рекомендацию, активность, нахождение файла внутри разрешённого каталога и SHA-256. Ответ содержит исходные байты, исходное имя и MIME; RTF не преобразуется.

Проверка реестра:

```bash
docker compose exec backend python -m app.cli.verify_contract_templates
```

## Развёртывание и обновление

До запуска администратор создаёт `contract_templates/` рядом с `docker-compose.yml` и копирует туда четыре файла с точными именами. Каталог исключён из Git. При отсутствии или изменении файла seed/startup завершается явной ошибкой. Пользовательские API не позволяют загружать, менять или удалять эти файлы.

Для добавления пятого/шестого договора администратор добавляет его метаданные и утверждённый SHA-256 в `app/contract_registry.py`, добавляет детерминированное правило и тесты, затем размещает оригинал в read-only каталоге.
